# CODE_REVIEW_GUIDELINES.md

Правила для ревью (человеком и ИИ) в moneyKeeper. Основа: [CODE_REVIEW_GUIDELINES Actual Budget](https://github.com/actualbudget/actual/blob/master/CODE_REVIEW_GUIDELINES.md), плюс правила про деньги и слои.

Находки делим на **A** (баг в том, что требует задача) и **B** (hardening гипотетического сценария). B в код не идёт без явного «да», к каждому B одна строка: какой существующий механизм уже покрывает сценарий и чего ему не хватает.

## Деньги и время

1. **Деньги только целым числом минорных единиц** (`amount_minor BIGINT`) и кодом валюты рядом. Никакого `float` в суммах, остатках и курсах-результатах.
2. **Курсы** хранятся как `NUMERIC`, пересчёт округляется в одном месте. Историческая запись показывается по текущему курсу, курс на день записи хранится справочно (для крипты обязательно: от него считается % прибыли).
3. **Даты** это дата в часовом поясе пользователя, отдельный тип, а не `time.Time` с полуночью. «Сегодня» считается в поясе пользователя.
4. **Остатки и «К распределению» не хранятся**, а считаются из транзакций и заложенных сумм. В хранилище только то, что ввёл человек (идея Actual).
5. **Несколько записей одной операции** (перевод, сплит, чек) пишутся в одной транзакции БД.

## Слои

6. Импорты только вниз: `repo → service → handlers/web`. SQL только в `repo`, правила в `service`, формат ответа в `handlers/web`.
7. Все тексты пользователю только через `i18n`. Захардкоженная строка в обработчике или на фронте это находка.
8. Отдельный слой DTO между моделями и JSON. Типы фронта генерируются из Go, а не копируются вручную.
9. Ошибки: sentinel в `models`, обёртка `fmt.Errorf("...: %w", err)`, ветвление через `errors.Is`.

## Настройки и подавления

10. **Не добавлять настройку на каждую мелочь.** Сначала спросить, решается ли это темой, дизайн-токеном или значением по умолчанию. Режим приватности это одна настройка, а не набор.
11. **Не добавлять новые подавления линтера** (`//nolint`, `eslint-disable`) и отключения строгой проверки типов без документированной причины. Чинить причину.
12. **Фронт:** `satisfies` вместо `as` (кроме защит рантайма с комментарием), без `any` и `unknown` без обоснования, `type` вместо `interface`, без `enum`.

## Тесты

13. Мало моков: деньги, бюджет и сверка проверяются на реальных структурах и реальной БД. Мок только для внешнего API (курсы, Telegram, LLM). Табличные тесты.
14. Репозитории проверяются интеграционными тестами с Postgres, остальное быстрыми модульными.

## Интерфейс

15. **Суммы выводятся табличными цифрами** (`tabular-nums`) через один компонент для денег. Тот же компонент отвечает за маскировку звёздочками.
16. Секреты, ключи и seed-фразы в коде и логах это блокирующая находка. Суммы и описания транзакций в логи не пишем.
17. Во внешние сервисы (LLM, курсы) уходят только агрегаты и коды валют, не сырые транзакции. Пользователь может отказаться от AI.
