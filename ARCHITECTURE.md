# Architecture

moneyKeeper это один Go-процесс: Telegram-бот, фоновые планировщики и JSON API для Telegram Mini App. Mini App это статическая сборка (Vite + React), которую раздаёт Caddy. Единственное хранилище это PostgreSQL. Документ описывает целевое устройство; кода пока нет, решения опираются на [tracker-bot](file:///C:/go/tracker-bot) и [Actual Budget](https://github.com/actualbudget/actual), но код оттуда не копируется.

## Слои и правила импортов

```
cmd/moneykeeper                 точка входа, логгер, конфиг
  internal/application          сборка: config → pg → bot → repo → service → handlers/web → планировщики
    internal/dispatcher         обновления Telegram → сессии, экраны, callback
    internal/handlers           экраны и сценарии бота
    internal/scheduler          уведомления: платежи по расписанию, напоминания, итоги недели
    internal/web (+ apidto, tgauth)   HTTP API для Mini App
      internal/service          бизнес-правила, валидация
        internal/repo           SQL, один репозиторий на область
          internal/pgclient     пул pgx
internal/models                 доменные типы, входные данные, sentinel-ошибки
internal/i18n                   каталог сообщений
internal/fx                     клиенты курсов
internal/llm                    клиенты LLM
pkg/*                           листовые помощники без импортов проекта (apptime, money, ...)
webapp/                         Mini App
migrations/                     SQL-пары up/down
```

Импорты только вниз:
- `repo` импортирует `models` и `pkg/*`. Без service, handlers, i18n.
- `service` импортирует `repo`, `models`, `fx`, `llm`. Не импортирует `handlers` и `web`.
- `handlers`, `dispatcher`, `scheduler`, `web` отвечают за представление: какой текст, какая клавиатура, какой HTTP-статус. SQL и `repo` там не вызываются.
- `web/apidto` это формат API. Модели наружу не сериализуются. Типы для фронта генерируются из DTO.
- Весь пользовательский текст только через `i18n`.
- `pkg/*` ничего не импортирует из `internal/`.

## Модель данных

Центральная сущность это **бюджет** (`budgets`), а не пользователь.

```
users ──< budget_members >── budgets
                              ├──< accounts       (cash | debit | credit, у карты есть визуал)
                              ├──< category_groups ──< categories
                              ├──< category_months  (budgeted_minor по категории и месяцу)
                              ├──< transactions     (kind: expense | income | transfer | opening, transfer_id для переводов)
                              ├──< schedules
                              ├──< debts            (конверт для «другого долга»)
                              └──< assets           (внебюджетные активы, крипта)
```

- Каждому пользователю при регистрации создаётся личный бюджет. Общий бюджет создаётся приглашением, участники равноправны. Пользователь может состоять в нескольких бюджетах и переключаться между ними.
- Все сущности принадлежат бюджету, поэтому у участников общего бюджета данные синхронизированы без отдельной логики. Приглашение хранится как упорядоченная пара с подтверждением.
- В первой версии всё в общем бюджете видят оба участника.
- Суммы это `amount_minor BIGINT` плюс код валюты, всегда целые. Курс хранится справочно на день записи (для крипты обязательно, по нему считается % прибыли).

### Что хранится, а что считается

Хранится только то, что ввёл человек: заложено по категории и месяцу, транзакции, расписания. Считается: потрачено, остаток категории, «К распределению».

```
остаток(месяц) = заложено + потрачено
               + (перенос включён ? остаток(прошлый месяц) : max(остаток(прошлый месяц), 0))
```

Флаг переноса (`categories.rollover`) стоит на категории, он заменяет «Rollover Overspending»: с переносом остаток и перерасход идут в следующий месяц, без него только плюс. У групп «На чёрный день» и «Цели накопления» перенос включён с самого начала. «К распределению» накопительное: все доходы (с начальными остатками) до конца месяца минус всё заложенное до него включительно, поэтому нераспределённое переходит само. Заложено хранится в `category_months` (категория, месяц, сумма), потрачено берётся из транзакций по курсу дня записи в базовой валюте, переводы в бюджет не входят. Сверка помечает транзакции флагом «сверено», расхождение закрывается только осознанной корректирующей записью.

### Транзакции

- Сплит это родительская запись и дочерние. В ядро учёта не вошёл, колонка `parent_id` добавится отдельной миграцией.
- Перевод это две связанные записи (`transfer_id`), в категориях не участвует.
- Сверка и перевод пишутся в одной транзакции БД.
- Сумма хранится со знаком: расход и уходящая нога перевода отрицательные. Остаток счёта это сумма его записей, по каждой валюте отдельно.
- У счёта есть основная валюта (`accounts.currency`) и флаг `multi_currency`. Обычный счёт принимает записи только в основной валюте, многовалютный в любой поддерживаемой. Запись всегда хранит свою валюту.
- Начальный остаток счёта это запись `opening`: доход в «К распределению» на день создания счёта.
- Удаление мягкое (`deleted_at`). Каждое создание, правка и удаление пишет событие в `transaction_events` с состоянием до и после.
- Перевод идёт в одной валюте, и её должны допускать оба счёта. Между валютами это обмен (`kind = exchange`): две записи с суммами, как провёл банк или биржа, курс сделки считается по ним. Обмен возможен и внутри одного многовалютного счёта.
- Счета делятся на внутри бюджета (карта, наличные) и вне бюджета (`wallet` кошелёк или биржа, `piggy` копилка, колонка `off_budget` считается из вида счёта). Остатки счетов вне бюджета и их начальные остатки в «К распределению» не входят.
- Деньги через границу бюджета: со счёта бюджета на счёт вне бюджета это расход конверта и у такого перевода или обмена обязательна категория (у перевода в копилку это конверт копилки); обратно, со счёта вне бюджета на счёт бюджета, это приход в «К распределению». Между счетами одной стороны категории нет и бюджет не меняется.
- Комиссия обмена со счёта внутри бюджета это обычный расход с категорией в той же группе записей (`transfer_id`), со счёта вне бюджета запись `fee` без категории, она только уменьшает портфель. Комиссия сети при переводе между кошельками одной монеты: ноги перевода разной величины (отправлено больше, чем пришло), сумма такого перевода не правится.
- Записи группы (обмен, перевод, комиссия) правятся и удаляются вместе; у обмена меняются только дата и заметка.
- Портфель (`GET /api/portfolio`) считается по средней цене покупки в лари: покупка монеты оценивается по отданной стороне обмена, продажа по полученной, начальные остатки и доходы в монете по курсу дня, комиссия сети и комиссия в монете уменьшают количество и не меняют стоимость покупки. Прибыль зафиксированная (продажи) и нереализованная (по текущему курсу).
- Копилка это счёт `piggy` вне бюджета с целью (сумма и дата, необязательные) и конвертом в группе «Цели накопления» (`accounts.category_id`). Пополнение это перевод со счёта бюджета в категорию конверта; счёт списания выбирается каждый раз.
- Быстрый ввод («кофе 5 EUR») разбирает `pkg/quickinput`, он общий для Mini App и будущего бота.
- Кредитная карта это счёт типа `credit`. «Другой долг» это конверт в группе «Долги». Расчёт платежа по картам отложен.

### Расписания

Правило повтора, дата следующего платежа, суммы точная, примерная или диапазон. Планировщик присылает уведомление в день платежа. Транзакцию автоматически не создаёт. Сопоставление внесённой траты с расписанием: окно ±2 дня, тот же счёт, переводы исключены.

## Поток обновлений бота

1. Диспетчер получает обновление Telegram и строит контекст: чат, пользователь, текст, часовой пояс, язык, активный бюджет.
2. Маршрутизация сообщения: команда → ожидаемый ввод → кнопки → свободный текст (быстрый ввод «кофе 5 EUR»). Для callback: подтверждение → маршрут по префиксу.
3. Обработчик вызывает сервисы, рендерит через клавиатуры и тексты `i18n`, отправляет ответ через интерфейс клиента Telegram (подменяется в тестах).
4. Планировщики работают рядом: тикер, список пользователей к уведомлению, `handlers` отправляет сообщение с явными идентификаторами.

## Mini App

- Vite + React + TypeScript, собранная статика, раздаётся Caddy, `/api/*` проксируется на приложение. API наружу не публикуется.
- Авторизация по подписи `initData` Telegram.
- Экраны: бюджет и конверты, песочница, отчёты и кружок, портфель (кольцо по % от капитала, переключатель на пузырьки по % прибыли), сверка, расписание.
- Единый компонент для денег: табличные цифры и маскировка звёздочками при включённом режиме приватности.
- Анимации: Framer Motion, графики `d3-shape` и `d3-hierarchy`.
- Типы API генерируются из `apidto`.

## Внешние сервисы

| Сервис | Для чего | Заметки |
|---|---|---|
| Нацбанк Грузии ✅ | официальные курсы USD, EUR, RUB к GEL на любой день | публичный JSON `/gw/api/ct/monetarypolicy/currencies/en/json/?date=`, без ключа, курс за `quantity` единиц |
| Binance ✅ | USDT и 20 монет (BTC, ETH, XRP, BNB, SOL, USDC, DOGE, TRX, ADA, LINK, AVAX, XLM, BCH, TON, LTC, DOT, SHIB, UNI, NEAR, ATOM) | дневная свеча `klines` пары EURUSDT, цена USDT в лари = (₾ за €) / EURUSDT, USDT не приравнивается к доллару. Монета = её цена в USDT на день × лари за USDT; берётся последняя свеча не позже конца дня, при пропуске торгов ближайшая предыдущая |
| CoinGecko | запасной источник, остальная крипта | бесплатный ключ, лимиты |
| LLM | анализ выписки, категории, подсказки | только агрегаты, пользователь может отказаться |

**Курсы и пересчёт ✅.** Опорная валюта лари, в таблице `rates (day, currency, gel_per_unit)` цена одной целой единицы в GEL. Курс дня пишется один раз (первый полученный не перезаписывается), поэтому суммы не «плывут». Ходим в источник лениво: при выдаче записей и счетов докачиваются дни без полного набора курсов, не больше 8 дней за запрос, сначала свежие. Недоступный источник не ломает ответ, суммы в базовой валюте просто `null`. Дата записи в будущем считается по курсу сегодняшнего дня.

Реестр валют (`pkg/money`): у каждой своя точность (BTC и ETH 8 знаков, SHIB 0, USDT 2), порядок показа и признак монеты. Точность уже заведённой валюты менять нельзя, хранимые суммы поплывут. Курсы монет запрашиваются только когда монета есть в записях или остатках, основные валюты (EUR, USD, RUB, USDT) тянутся всегда.

Валюта показа выбирается на клиенте и хранится на устройстве. Сервер пересчитывает суммы в валюту из параметра `in` у `GET /api/accounts` и `/api/transactions` (пусто значит базовая валюта бюджета), поля `base_*` это суммы в этой валюте. `GET /api/rates?in=` отдаёт курсы всех валют к ней на сегодня десятичными строками.

Пересчёт делает `pkg/money.Convert`: точная арифметика `big.Rat`, одно округление в конце, половина от нуля. Сумма в базовой валюте нигде не хранится, считается при выдаче: запись по курсу своего дня (`base_minor`), остаток счёта по курсу сегодняшнего дня, расходы счёта по сумме дневных итогов, каждый день по своему курсу. Итог счёта может отличаться от суммы записей на копейки из-за округления дневной суммы.

## Ошибки

- Все sentinel в `models/errors.go`. `repo` переводит `pgx.ErrNoRows` и нарушения ограничений в них, сервисы добавляют ошибки валидации.
- Оборачиваем при подъёме: `fmt.Errorf("...: %w", err)`. Ветвление через `errors.Is`.
- Обработчик бота сопоставляет ошибку с ключом `i18n`, `web` с устойчивым кодом ошибки.

## Время

- В БД `TIMESTAMPTZ`, в Go UTC.
- `pkg/apptime` переводит пояс пользователя в `*time.Location` и считает границы дня, недели, месяца. «Сегодня» считается в поясе пользователя.
- Календарный день это отдельный тип даты, а не `time.Time` с полуночью.

## Приватность и безопасность

- Шифрование хранилища, удаление всех данных по команде.
- Режим скрытия сумм: звёздочки вместо цифр за месяц, переключается кнопкой в Mini App.
- В чат-уведомлениях суммы по умолчанию не маскируются.
- Во внешние сервисы уходят только агрегаты и коды валют. Приватные ключи и seed-фразы не хранятся.
- Суммы и описания транзакций в логи не пишутся.

## Тесты

- Модульные тесты рядом с кодом, табличные, с ручными подменами, моки только для внешних API.
- Репозитории проверяются интеграционными тестами с Postgres (`-tags=integration`).
- Фронт: vitest для чистой логики.

## Деплой

`docker-compose`: `db`, одноразовый `migrate`, `moneykeeper-app`, `moneykeeper-webapp` (Caddy). Сервисы с префиксом `moneykeeper-`, потому что `moneykeeper-webapp` подключён к общей сети `tracker-bot_default`, где имена `app` и `webapp` уже заняты tracker-bot. Сейчас в compose только `app` и `webapp`, `db` и `migrate` появятся вместе с первой миграцией. Миграции это SQL-пары up/down.

Проект не зависит от tracker-bot и его Caddy. Mini App в Telegram открывается только по HTTPS с настоящим сертификатом, адрес задаётся переменной `WEBAPP_URL` и в BotFather.

**Разработка ✅.** Туннель ngrok со статическим доменом (`https://<имя>.ngrok-free.app`) с компьютера разработчика на локальный порт. VPS не нужен. Адрес один раз вписывается в `WEBAPP_URL` и BotFather.

**Продакшен ✅.** На VPS `132.243.194.137` порт 443 занят чужим сервисом, порт 80 и 8443 держит Caddy из tracker-bot (`tracker-bot-webapp`), поэтому свой сертификат Let's Encrypt там получить нельзя. Проект подключает контейнер `moneykeeper-webapp` к сети `tracker-bot_default` под этим именем, а в Caddyfile tracker-bot добавляется блок из одной строки, как у Abalis. Адрес `https://hoardkeeper-132-243-194-137.sslip.io:8443` (порт обязателен), имя `sslip.io` само указывает на IP из имени, если IP VPS изменится, имя придётся менять в `.env`, Caddy и BotFather.

```
hoardkeeper-132-243-194-137.sslip.io {
	tls {
		issuer acme {
			disable_tlsalpn_challenge
		}
	}
	encode zstd gzip
	reverse_proxy moneykeeper-webapp:80
}
```

`/api/*` и статику разделяет `moneykeeper-webapp` внутри нашего `docker-compose`. Caddyfile tracker-bot вшит в образ `tracker-bot-webapp`, правка делается в каталоге проекта на VPS и применяется пересозданием контейнера. Это изменение чужого проекта на проде.

## Известные риски, закладываем сразу

- Граница транзакции БД над несколькими репозиториями (помощник unit of work).
- Отдельный тип даты и часовые пояса.
- Генерация типов фронта из Go.
- Общий запуск планировщиков с логгером на каждую задачу.
